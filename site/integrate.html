DEVELOPER / AI INTEGRATION

Resolve one identity.
Inspect the claims behind it.

VERQIVIA uses ordinary HTTPS, JSON and OpenAPI. A consuming application does not need to scrape the web page or run a proprietary VERQIVIA SDK.

Open demo profile → Open OpenAPI contract
01

Resolve

Start with a VERQIVIA ID, or discover a participating domain's /.well-known/verqivia.json pointer.

02

Read

Request GET /v1/identity/{nothing_id}/profile and consume the portable profile as JSON.

03

Decide

Inspect claim status, scope, current event, evidence references, lifecycle and—when present—cryptographic proof references.

Illustrative response shape. Production API host, authentication and data vary by deployment.

A

Procurement

Resolve the supplier identity, inspect the exact claim you care about and apply your own onboarding policy.

B

Marketplaces

Store the VERQIVIA ID as a durable reference and re-check lifecycle state instead of copying a badge once.

C

AI Agents

Use the profile as one verification input before relying on unfamiliar business identities, domains or relationships.

IMPORTANT

Do not turn one status into a universal trust score.

A verified domain claim is not proof of financial health, reputation, legal ownership or every other fact about the organization.
